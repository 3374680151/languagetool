## 一、产品定位（继承自 10）

### 1.1 一句话

给想用英文写博客的中文作者一个**边写边学**的写作台：左边写英文，右边即时看到中文回译；写错的单词与语法被逐条指出并讲清为什么；查过的词、犯过的错自动变成你的学习材料，复习时挖空的是**你自己写过的句子**。写的多了，英文就会了。

### 1.2 两条硬门槛

| 编号 | 门槛 | 怎么量 |
| --- | --- | --- |
| G-1 | 首次可用 | 打开写作台到拿到第一段中文回译 ≤ 3 秒，期间 0 次配置操作 |
| G-2 | 零配置 | 默认模型开箱即用；全站不存在"请填写 API Key"这种拦路界面 |

### 1.3 判断标准（用来砍需求）

新功能必须服务这三件事之一，否则不做：

- ① **写对**——回译确认、纠错；
- ② **学会**——查词收藏、再用、复习、错误本（学习材料一律来自你自己的写作）；
- ③ **发出去**——导出、读者侧。

### 1.4 明确不做

| 不做 | 原因 |
| --- | --- |
| 应试学习形态：通用词库打卡、选择题/拼写测试、学习时长统计、连续天数、排行榜 | 学习材料只来自你自己的写作（DR-12）：工具帮你写，不替你上课；词表内"使用次数"计数字段不算统计看板 |
| 文档处理（PDF / DOCX / 整页对照导入） | 不是博客场景 |
| 多引擎评测、翻译质量打分 | 对写作者没有直接价值 |
| 多租户 SaaS、账号体系 | 个人站点，匿名即可 |
| 站长管理后台页面 | 配置走环境变量 + 网关配置文件 |
| 富文本编辑器 | 段落级替换会和富文本内部模型打架 |
| 图片/漫画/圈选/局部/视频字幕/输入框翻译、本地模型、本地 TTS、智能高亮、分享卡、快捷翻译方案、配置云备份 | 浏览器扩展专属场景或与写作台无关（详见 §3 取舍表） |

### 1.5 暂缓池（本期不做、P7 之后按需评估）

整段/全文朗读（词卡上的单词朗读除外——随 P4 词卡提供，浏览器 speechSynthesis，见 §八）、翻译历史、个人译法库（改译记忆）、多语言界面、AI 阅读讲解卡、Anki 导出、完整版 ECDICT 词库按需下载、用量看板 UI（站长用 LiteLLM 统计替代）。

## 二、角色与场景

| 角色 | 是谁 | 关心什么 |
| --- | --- | --- |
| 作者（主） | 用英文写博客、想借此把英文学起来的中文作者 | 写对、记住单词、掌握语法、发出去 |
| 读者（次） | 打开博客的人 | 看懂英文，或看中文对照 |
| 站长 | 部署这套东西的人 | 别超支、别被刷、别挂 |

**主场景（写一篇英文博客，边写边学）**：
1. 打开写作台，左边英文、右边中文（默认英→中，不用选）；
2. 写一段英文 → Ctrl/⌘+Enter → 右边出中文回译，确认"写的是我想说的"；
3. 点"纠错"：逐条看**错在哪、为什么错** → 接受/忽略；接受的自动进错误本，以后还能复习；
4. 写作中遇到没把握的词 → 点词查释义 → 一键收藏（带着你写的这句进词表）；
5. 专有名词/固定译法加进术语表；
6. 明天再写：收藏的词到期就复习——挖空的是你自己写的句子；写新段落时把收藏的词再用上（再使用会被记下）；
7. 导出 Markdown（英文 / 中英对照）→ 发布。

**次场景（读者读一篇英文博客）**：打开页面 → 选中段落或点"翻译" → 看到中文 → 选中生词看释义。

### 4.1 写作台布局与输入（FR-1）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-101（继承） | 左英右中双栏对照，默认语言对 英→中 | 首次打开，左边标签"English"、右边"中文"，不需要手动选语言 |

### 4.2 纠错（FR-2，核心功能）

> 与翻译同级，不是附属。写英文的人最需要"哪里写错了"，不是"再翻一遍"。

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-201（继承） | 单词级纠错：拼写错误、用词不当（word choice）、单复数 | 一段里故意写 2 个拼写错 + 1 个用词不当，全部被指出 |
| FR-202（继承） | 语法级纠错：主谓一致、时态、冠词、介词、句子结构 | 一段里故意写 3 处语法错，全部被指出 |
| FR-203（修订） | 每条建议包含：原文片段→建议改法→类别→**理由**；理由必须是教学解释（错在哪、规则是什么、为什么这样改），不接受"表达欠佳"式笼统评价 | 4 个字段齐全；类别属于拼写/语法/标点/风格/用词；每条理由能让人学到一条可复用的规则 |
| FR-204（继承） | original 必须是原文子串，否则丢弃（不让模型算偏移量） | 模型返回不存在的片段时，该条被丢弃且不报错 |
| FR-205（继承） | 逐条接受/忽略，接受后重新校验剩余条目的位置 | 接受第 1 条后，第 2/3 条仍能正确定位 |
| FR-206（继承） | 只检查英文段落，中文段落跳过 | 中文段没有纠错入口 |
| FR-207（继承） | 不自动跑，必须手动触发（写的时候不要打断思路） | 输入过程中不弹任何建议 |
| FR-208（继承） | 不做整段重写，只给逐条建议 | 界面不出现"一键改写全文" |
| FR-209（继承） | 没有错误时明确说"这段没有发现问题"，不是空白 | 正确段落点纠错，有明确反馈 |

| --- | --- | --- |
| FR-1201 | 写作中查词即收藏：点词弹卡带"收藏"按钮，收藏时自动带上你写的这句作为上下文；随访客身份，无账号 | 写作台查词→收藏→词表出现该词，且原句就是刚写的句子 |

| FR-1203 | 错误本：纠错建议被"接受"时自动存一条（原片段、改法、类别、理由、日期）；错误本可按类别筛选回看、可单条删除；"忽略"不存 | 接受 3 条建议后错误本出现 3 条；删除后不再出现；忽略的建议不入本 |
| FR-1204 | 挖空复习：材料 = 收藏词（在**你的原句**里挖空）+ 错误本条目（挖空正确改法）；翻卡两键评分（记住/没记住）；间隔调度 10 分钟/1/3/7/14/30 天，"没记住"回退；到期数量在词表页入口显示，不弹窗、不常驻顶栏 | 收藏词到期后出现在复习队列；评分"没记住"按间隔回退重排；卡片例句是你自己写的句子 |
| FR-1205 | 学习资产可导出可删除：词表 + 错误本支持 JSON 导出、确认后清空 | 导出 JSON 含词/原句/错误条目；清空需二次确认，完成后库为空 |

### 7.3 后端分层规则

- `handler` 只做参数解析与响应组装，业务规则在 `service`，上游协议在 `gateway`，SQL 在 `store`；
- 错误一律构造为 `errs` 中的错误码，禁止 handler 直接 `c.JSON(500, ...)`；
- `service.translate`：先逐段校验（空→skipped、超长→TEXT_TOO_LONG、语言码→UNSUPPORTED_LANGUAGE），再对合法段并发（信号量默认 5）调用 `gateway`，单段失败只影响该段（FR-303/304/305）；
- 计费在结果结算时进行：成功非 skipped 段才计数，付费线路成功才计字符（FR-604）；
- 纠错结果在 `service.proofread` 内做子串校验：`!strings.Contains(text, s.Original)` → 丢弃该条（FR-204），全部被丢则返回"没有发现问题"（FR-209）。

### 7.6 网关与模型池

**上游形态（DR-9）**：Go 网关只讲一种协议——OpenAI 兼容 chat/completions。推荐把 L1/L2 的上游指向 **LiteLLM**，由它完成协议转换（OpenAI / Anthropic / Gemini 等原生协议统一进来）、渠道与密钥管理、按模型的用量/费用统计。LiteLLM 是**可选外挂**：不部署时 `FR_BASE_URL` 直接指向任意 OpenAI 兼容端点，应用行为完全一致（NFR-4 不受影响）。LiteLLM 本地转发开销计入超时预算，NFR-1 走查按真实部署链路计时。

**三层模型（FR-4）**：
- **L1 默认**：`models.json` 中 `role:"primary"` 且 `enabled:true` 的模型，经 LiteLLM（或直连端点）调用；站长不配则为"未配置"态（六态之一，页面照常可用）；
- **L2 站点池**：`models.json` 中其余 `enabled:true` 的模型，出现在顶栏下拉（FR-402），带 quality/speed/cost 标签；实际可调用性以 LiteLLM 模型清单为准；
- **L3 自定义**：访客请求携带 `{baseURL, apiKey, model}`，服务端即用即弃转发（FR-403/404），失败自动回落 L1 并提示（FR-405）；**不经过 LiteLLM**（访客密钥不进站长网关），首版单套（已拍板）。

**密钥边界（FR-1002）**：各供应商密钥归属 LiteLLM 配置或环境变量，Go 应用只持有 LiteLLM 端点与虚拟密钥（`FR_API_KEY`）；两者都不入库、不下发、不写日志。

**降级链**：付费主线路 →（站点日字符触顶 FR-603 / 调用失败 / 多 Key 耗尽 FR-1102）→ 免费后备线路 MyMemory（**Go 直接实现，不经 LiteLLM**，DR-10）→ 仍失败才向该段返回 failed。降级成功时响应带 `degraded:true` + 原因（FR-306），且不计付费字符（FR-604）。

**结果校验（继承扩展 broker 经验）**：拒绝空译文、拒绝原文回显、拒绝目标语种不符；三者都判为该段失败，不把坏结果交给用户。

**巡检与清单对账（FR-408/FR-1103）**：`deploy/models.json` 只描述展示（标签、enabled），实际可调用清单以 `GET {base}/v1/models` 为对账基准（LiteLLM 场景即查 LiteLLM）；启动时 + 每小时对账，缺失/多出的模型产生 WARN + `gateway:"degraded"` + 设置页横幅；连续 2 次失败的模型剔除出下拉，恢复后自动回来。直连模式（无 LiteLLM）时对直连端点做同样对账。

**测试基座**：`cmd/mockupstream` 提供可注入成功/失败/超时/超长/空响应的假 OpenAI 兼容上游，使无真实 Key 的环境也能完整自测六态、降级链、限频与超时；验收循环（§十一）与 NFR-14 门禁依赖它。

### 7.7 Prompt 设计

集中放 `gateway/prompt.go`，全部模板可被环境变量覆盖（站长调优不改代码）：

| 模板 | 要点 |

## 八、查词弹卡详细设计（原 12 号文档，已并入）

> 定位：把"写作中遇到没把握的词"变成一次 **3 秒内的学习动作**——查到 → 看懂 →
> 收藏（带着你写的句子）→ 之后复习时挖的就是这句。它是学习闭环（FR-12xx）的入口。
> 参考基线：浏览器扩展现有实现（划词词卡、ECDICT 词典链路、web/word-popup.js），
> 但交互按写作台场景重新裁剪。验收按 §8.6 的 AD 清单逐条打勾。

### 8.1 目标与边界

**一句话**：写作台和词表页里，双击或划选英文单词，原地弹出释义卡，一键收藏进生词本。

对齐 §1.3 判断标准：本功能服务 ②"学会"（查词收藏的入口）与 ①"写对"（用词拿不准时当场确认）。

**做什么**：单词查询（词典优先）、短语搭配解释（≤4 词）、一键收藏（自动带所在句）、单词朗读、已收藏状态展示。

**不做什么（明确取舍）**：

| 不做 | 理由 |
| --- | --- |
| 划选整句弹翻译卡 | 写作台的整段回译已覆盖；且与编辑器光标操作打架 |
| 多家在线词典聚合 | 扩展的经验教训：协议杂、不稳定、易被封；收敛为 ECDICT + 模型兜底两极（对齐 DR-7） |
| 卡片内做笔记/换词库/编辑释义 | 卡片只读 + 收藏；管理动作去词表页，保持卡片 3 秒内可离开 |
| 中文词查询 | 查词只服务英文写作语言；写作语言为中文（语言对反转）时不触发（对齐 FR-206 精神） |

### 8.2 触发（什么时候弹）

> 触发体系直接沿用浏览器扩展划词翻译的成熟设计（划选即弹 / 图标确认 / 修饰键 / 触发延迟 /
> 自动收起），按"编辑器场景"裁剪：砍掉与写作光标操作打架的模式，保留三种可切换模式 +
> 一个固定入口。默认值与扩展一致 = **划选即弹**。

**三种触发模式（设置页可切换，刷新后保留，对应 FR-1001）**：

| 模式 | 行为 | 适合谁 |
| --- | --- | --- |
| 划选即弹（direct，**默认**） | 双击单词或划选 1–4 词，鼠标松开即弹卡 | 与扩展阅读体验一致，"选中就要查" |
| 浮标确认（icon） | 选中后只在选区旁显示一个小浮标按钮，**点浮标才弹卡** | 写作中经常选中文字做替换/删除的人——选区本身不再触发查询，零打扰 |
| 修饰键（modifier） | 按住 `Alt`（可改 Ctrl/⌘）+ 划选才弹卡 | 键盘流；平时完全不干扰 |

**所有模式共用的固定规则**：

| 动作 | 行为 |
| --- | --- |
| 单击 | **三种模式下都永不弹**——单击是光标定位的高频操作，误触即毁掉功能 |
| 划选 ≥5 个词 | 不弹（视为句子，回译已覆盖） |
| 右栏中文 / 写作语言为中文 | 不弹（对齐 FR-206 精神） |
| 词表页搜索框 | 输入词 + 回车/按钮 → 在固定位置弹卡（不受模式影响） |
| 400px 窄屏 | 长按选词出系统选区 → 按当前模式处理；卡片宽度自适应（≤320px，AD-8） |
| 触发延迟 | 划选即弹模式加 200ms 选区落定延迟：替换式选中（选完立刻打字）不闪卡 |
| 自动收起 | 点空白 / `Esc` / 滚动 / 开始输入 / 切换段落——任一即关 |
| 自动朗读 | 设置开关，默认关；开启后弹卡立即朗读该词，关闭时仅点朗读按钮发声 |

**不移植的扩展模式及理由**：

| 扩展模式 | 处置 | 理由 |
| --- | --- | --- |
| 悬停触发（hover） | 不做 | 编辑器里鼠标掠过就查询，写作场景纯干扰；SDK 阅读场景（P6）再评估 |
| 右键菜单（contextMenu） | 不做 | 需覆盖编辑器原生右键（拼写检查/粘贴），成本高收益低 |
| 圆点（dot） | 并入浮标 | 与 icon 同型，二选一足够 |
| 多套自定义方案（quick-translation） | 不做 | 单人写作台用不上多方案；三种模式 + 固定入口已覆盖 |

**预处理规则**（弹卡前执行）：

1. 选中内容清洗：去首尾标点、统一小写用于查询（展示保留原样）；
2. 纯数字、单个标点、纯符号 → 不弹；
3. 连字符词（`state-of-the-art`）→ 整体查询，失败再去连字符查；
4. 同一词 300ms 内重复触发 → 复用已有卡片，不发请求；
5. 会话内查过的词 → 前端 session 缓存直接命中。

### 8.3 卡片内容（弹什么）

**词典态（ECDICT 命中，目标 <100ms）**：

```text
┌────────────────────────────────┐
│ recall   /rɪˈkɔːl/   v. n.     │
│ [CET4] [考研] [常用词]           │ ← 考纲/词频标签（ECDICT tag/collins/bnc 字段）
│ v. ① 回忆起；回想起              │
│    ② 召回；收回                  │
│ n. ③ 记忆力；召回               │
│ ⓘ 查询的是 recalled —— 原形 recall │ ← 仅当词形还原生效时显示
│ ────────────────────────────── │
│ 🔊 朗读    ☆ 收藏               │
└────────────────────────────────┘
```

**在线态（ECDICT 未命中 → 模型解释）**：

```text
┌────────────────────────────────┐
│ gerrymander                     │
│ ⓘ 在线解释（AI 生成，仅供参考）    │ ← 来源必须标注
│ v. 为选举利益不公正地划分选区      │
│ e.g. The district was gerrymandered in 2020. │
│ ────────────────────────────── │
│ 🔊 朗读    ☆ 收藏               │
└────────────────────────────────┘
```

- 拼写错误的词走同一通道，模型提示词要求先指出"可能是 XXX 的拼写错误"再给释义（AD-5）；
- **短语态**（划选 2–4 词）：给搭配解释 + 一个例句，同样标注在线来源；
- 两种来源共用同一张卡，只是内容字段与来源标注不同。

**已收藏态**：收藏按钮变为不可再点的状态行 `✓ 已收藏 · 写作中用过 3 次`。卡上**只加不减**：取消收藏去词表页管理，避免误删学习资产。

| 字段 | 词典态来源 | 在线态来源 |
| --- | --- | --- |
| 词头 / 音标 / 词性 / 多条释义 / 考纲标签 | ECDICT 精简库（embed，约 3000 高频词，DR-6） | — |
| 释义 + 例句 + 拼写纠错提示 | — | 模型（经网关，§7.6） |
| 词形还原提示 | 服务端统一词形还原器 | 同左 |
| 已收藏状态 / 使用次数 | `words` 表按访客查询 | 同左 |

### 8.4 交互（怎么弹、怎么关）

| 项 | 规则 |
| --- | --- |
| 位置 | 锚定选区，优先在下方 8px；空间不足翻转到上方；左右夹紧在编辑器容器内，不溢出视口 |
| 非模态 | 弹卡不阻塞写作，可继续打字 |
| 关闭 | 点空白、`Esc`、滚动、切换段落、开始输入——任一即关 |
| 加载 | ECDICT 命中几乎即时；走模型 >150ms 时卡内显示骨架（六态之"加载"）；失败卡内给"没查到 + 重试"（六态之"失败"） |
| 朗读 | 浏览器 `speechSynthesis`（en-US 优先），零服务端成本；不支持的环境按钮置灰 |
| 收藏中 | 点击收藏 → 按钮进入加载态 → 成功变已收藏态；失败卡内提示可重试 |

### 8.5 数据与后端

**查询链**：

```text
前端 session 缓存 → GET /api/dict/:word
                     → 服务端内存缓存（FR-1101）
                     → ECDICT embed 查询（命中即返回，source=ecdict）
                     → 模型兜底（source=model；限频 10 次/分钟/访客；
                        结果写回内存缓存，相同词第二次不再打模型）
```

**限频与配额**：查词**不计翻译配额**（FR-604 不受影响）；模型兜底单独限频（默认 10 次/分钟/访客，环境变量可调），超限返回 429 + 卡内"稍后再试"。

**响应结构**（`GET /api/dict/:word`）：

```jsonc
{
  "word": "recall",              // 归一化查询词
  "query": "recalled",           // 原始选中词（与 word 不同时，前端显示词形还原提示）
  "phonetic": "/rɪˈkɔːl/",
  "pos": "v. n.",
  "senses": [ { "pos": "v.", "def": "回忆起；回想起" } ],
  "tags": ["cet4", "ky"],        // 考纲标签，可空
  "source": "ecdict",            // ecdict | model
  "example": null,               // 仅 model 态
  "collected": { "yes": true, "useCount": 3 }   // 按当前访客查 words 表
}
```

**收藏**（FR-1201 落地点）：`POST /api/words`，`context_sentence` = **词所在的完整句子**——

- 提取规则：从选区位置向前、向后找最近的句末标点（`.` `?` `!`），句长截断上限 300 字符；找不到句末标点时取整段；
- 幂等：同访客同词重复收藏返回已有记录（不报错、不重复建行），卡片据此显示已收藏态；
- 词表页搜索框发起的收藏允许 `context_sentence` 为空——复习时该词退化为"词 → 释义"卡（FR-1204 兼容）。

**隐私**：查询行为本身不落库（NFR-6）；只有点收藏才写入 `words` 表片段。

## 九、验收（继承 10 §7）

1. **功能验收**：逐条打勾 §4 全部 FR；每条都要有可复现的操作步骤和预期结果，不接受"应该可以"。
