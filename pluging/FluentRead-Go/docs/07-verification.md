# 验证与体验迭代流程

> 代码写完之后**不是结束**。这份文档规定怎么逐个功能验证、怎么以用户身份体验、
> 怎么把体验问题变成下一轮的修改清单。

---

## 一、三个角色，不许混

| 角色 | 只做这件事 | 禁止 |
| --- | --- | --- |
| **用户** | 真实地写一篇博客，记录"哪里难受" | 不许解释技术原因、不许提方案 |
| **产品** | 把"难受"翻译成问题条目并定级 | 不许替开发写代码 |
| **开发** | 按定级修复，回归验证 | 不许自行降级或跳过 P0 |

关键约束：**用户视角的反馈必须发生在看代码之前**。看过实现就会开始替它辩护。

---

## 二、功能清单（F-01 ~ F-20）

每轮**全量跑一遍，不抽样**。抽样会漏掉"上轮改好了这轮又坏了"。

| ID | 功能 | 验证方法 | 对应任务 |
| --- | --- | --- | --- |
| F-01 | 打开站点直接进写作台 | 访问 `/`，不应出现落地页或多余跳转 | T-203 |
| F-02 | 分段翻译全部 | 粘 5 段中文，`Ctrl+Enter`，5 段都出英文 | T-205 |
| F-03 | 单段翻译 | 光标在某段，`Ctrl+Shift+Enter`，只有该段变 | T-205 |
| F-04 | 失败隔离 | 断网后翻 3 段，界面标红可重试，恢复网络重试成功 | T-205 |
| F-05 | 译文可编辑且受保护 | 改一句，再点重译，应弹"是否覆盖" | T-206 |
| F-06 | 纠错出列表 | 粘一段有 3 处错的英文，点纠错，出 3 条建议 | T-306 |
| F-07 | 接受/忽略纠错 | 接受一条，原文对应片段被替换；忽略一条，原文不变 | T-306 |
| F-08 | 术语新增与命中 | 加"检索增强生成 = retrieval-augmented generation"，翻含该词的段落 | T-405 |
| F-09 | 术语未遵循标黄 | 故意让模型不照做，该段应标黄提示 | T-407 |
| F-10 | 选词弹词卡 | 选中 `retrieval`，400ms 内出音标+词性+释义 | T-406 |
| F-11 | 选句弹译卡 | 选中一整句，出译文 | T-406 |
| F-12 | 收藏带上下文且去重 | 收藏同一个词两次，词表里只有一条，上下文更新 | T-502 |
| F-13 | 词表搜索/删除/导出 | 搜"retrieval"命中；删除有 10 秒撤销；导出 JSON 可读 | T-503 |
| F-14 | 切换模型 | 下拉切换，译文风格/速度有可见差异 | T-204 |
| F-15 | 自定义模型（L3） | 填自己的 baseURL+key，能用；填错自动回落默认并提示 | T-702 |
| F-16 | SDK 划词 | 静态 HTML 加一行 script，选中英文出中文 | T-604 |
| F-17 | 限额降级 | 把日限额调到 1，第二次请求应提示"已降级"而非报错 | T-107 |
| F-18 | 未配置提示 | 清空模型配置，界面应提示"本站未开启"，不白屏 | T-208 |
| F-19 | 导出 Markdown | 导出文件用编辑器打开，双语结构正确 | T-207 |
| F-20 | 主题切换 | 切深色，逐页看文字与边框是否可读 | T-202 |

## 三、六态检查（每个数据区域都要过）

| 态 | 怎么造 | 通过标准 |
| --- | --- | --- |
| 加载 | 网络限速 | 有骨架屏或进度，不是空白 |
| 空 | 新访客、无词表 | 有说明 + 一个可点的动作 |
| 失败 | 断开网关 | 显示原因 + 重试按钮 |
| 超时 | 网关指向黑洞地址 | 显示已等待秒数 + 取消 |
| 限额 | 日限额设为 1 | 说明剩余与恢复时间，不报 500 |
| 未配置 | 清空 `FR_DEFAULT_MODEL` | 说明缺什么，不是白屏 |

## 四、每轮四步

```
① 全量走查     用户身份，F-01～F-20 逐项操作，留证据
      ↓
② 提意见       只说"我在做 X 时，因为 Y，导致 Z"，不提方案
      ↓
③ 定级         产品把每条归为 P0/P1/P2，写进本轮清单
      ↓
④ 修复 + 回归  开发修完，重跑本轮全量走查
```

**P0 未清零，不许进下一轮。** 这是唯一的硬性闸门。

---

## 五、问题记录格式

```markdown
### BUG-R2-004

- 功能：F-06 纠错出列表
- 严重度：P0
- 现象：点纠错后一直转圈，30 秒后无任何提示
- 复现：粘 3 段英文 → 点"纠错" → 等待
- 期望：30 秒内出结果，或明确提示超时并可重试
- 证据：截图 1 张 + network 面板显示 /api/proofread 挂起 + console 无输出
```

| 严重度 | 判定 | 处理 |
| --- | --- | --- |
| **P0** | 功能不可用 / 数据丢失 / 页面报错 / 违反"零配置" | 本轮必须清零 |
| **P1** | 能用但难受：文案误导、位置别扭、多一步操作 | 每轮至少修一半 |
| **P2** | 打磨：间距、措辞、动效 | 最后统一收 |

## 六、轮次

| 轮 | 主题 | 重点看 | 出口 |
| --- | --- | --- | --- |
| **R0** | 基线 | 全部 20 项跑一遍，只记录不修 | 缺陷清单 v0，P0 数量已知 |
| **R1** | 零配置首译 | 清空浏览器打开 → 到看到第一个译文 | ≤ 3 秒，0 次配置，0 报错 |
| **R2** | 写 | F-02~F-05、F-08、F-09、F-19 | 一篇 800 字中文能翻完并改完 |
| **R3** | 查 | F-10~F-13 | 词卡准确，收藏去重正确 |
| **R4** | 读 | F-16 | 博客页面一行 script 可用 |
| **R5** | 稳定性 | F-04、F-17、F-18 + 六态 + 深色 + 375px | 控制台零报错，六态齐全 |

R5 之后如果 P0 清零、P1 剩余 ≤ 3 条，可以发布；否则加一轮 R6。

---

## 七、证据要求

每条问题必须带**至少两样**：

| 证据 | 怎么留 |
| --- | --- |
| 截图 | 全屏，含地址栏 |
| Network | 失败请求的状态码与耗时 |
| Console | 报错原文，不许只写"有报错" |
| 录屏 | 首译计时、交互卡顿必须录 |

**不接受**"我试了不好用"这种没有证据的反馈。

---

## 八、自动化冒烟（每次改动跑）

用 Playwright 覆盖主路径，**不替代**人工走查，只用来防止改坏。

| 用例 | 断言 |
| --- | --- |
| `smoke-translate.spec` | 粘 2 段 → 翻译 → 两段都有非空译文 |
| `smoke-proofread.spec` | 粘错句 → 纠错 → 至少 1 条建议 → 接受后原文变化 |
| `smoke-vocab.spec` | 收藏 → 刷新 → 词表仍有该词 |
| `smoke-quota.spec` | 限额 1 → 第二次请求返回 429 且带 hint |
| `smoke-sdk.spec` | 加载 embed 页 → 选中文字 → 气泡出现 |
| `smoke-console.spec` | 上述每条路径结束时 console 无 error |

最后一条是总闸门：**任何一条路径控制台有 error，这轮不算过。**

## 九、用户视角怎么"体验"

不要按功能清单点按钮——那是测试，不是体验。按真实任务做：

> **任务**：把昨天写的一篇 800 字中文博客，翻成英文，改到能发出去。

过程中只记三件事：

1. **卡在哪**（哪一步不知道该干什么）
2. **等在哪**（哪里等得心烦，超过 3 秒就记）
3. **不敢信哪**（哪个译文/建议你不敢直接用）

这三类才是真正要改的东西。按钮颜色不好看排在最后。

---

## 十、通过门槛

发布前必须同时满足：

- [ ] F-01 ~ F-20 全部通过，无 P0
- [ ] 六态在写作台与词表都齐全
- [ ] 清空浏览器打开，≤ 3 秒看到第一个译文，0 次配置
- [ ] 全站搜不到"请填写 API Key"这类界面
- [ ] 控制台在 6 条冒烟路径上零 error
- [ ] 深色模式逐页可读
- [ ] 375px 宽无横向滚动
- [ ] SDK gzip < 30KB
