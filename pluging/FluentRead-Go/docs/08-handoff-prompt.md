## 1. 这个项目为什么存在

FluentRead 原本是一个浏览器扩展（WXT + Vue 3），有全文翻译、划词翻译、词典、词表等 28 个功能模块。
站长不想让访客为了用这些功能去装扩展，所以要做一个**网站**，把扩展能力内嵌进去：

- 访客打开博客或文档站，选中文字就出译文，点单词就出词典，**不装扩展、不注册、不填 API Key**
- 站长只在页面加一行 `<script src=".../fluentread-sdk.js">`，界面跑在 Shadow DOM 里，不污染宿主页面
- 核心场景是**写博客**：写中文出英文、写英文边写边查、全篇术语一致
- 学到的词要留存，带原句，能复习

### 两条硬门槛，任何一条破了就是失败

1. **零配置**：读者从第一次访问到拿到第一段译文 ≤ 3 秒，配置动作 0 次
2. **任何"请填写 API Key"的界面都不许存在**（访客侧）。站长自己配模型是另一回事

已有文档是权威依据，**先读再写**：

## 3. 环境陷阱（踩过，别再踩）

1. **配置读的是 `FR_` 前缀**：`FR_ADDR`、`FR_DB_PATH`、`FR_GATEWAY_BASE`、`FR_GATEWAY_KEY`、`FR_DEFAULT_MODEL`、`FR_QUOTA_DAILY`、`FR_RATE_LIMIT`。写裸 `PORT` 会静默回落到 `:8080`。
2. **8080 与 18080 已被别的服务占用**。启动一律用随机空闲端口，不要写死。
3. **curl 打本机必须加 `--noproxy '*'`**，否则环境里的 `HTTP_PROXY=127.0.0.1:57645` 会返回一个假的 `{"code":0,"message":"success"}`。
4. **后台进程用 `PID=$!` 显式 kill**。`pkill -f` 和 `&` 写在同一行会把刚起的进程一起杀掉。
5. 本机没有 docker / helm / kubectl，只有 ssh/scp。`make up` 跑不了，本地验证走 `make build` + 直接执行二进制。

## 4. 阶段 A：P1.5 公开前的护栏

### 现状（这是缺陷，不是待办建议）

- `FR_QUOTA_DAILY` 和 `FR_RATE_LIMIT` **被解析、被上报，但从未被校验**
- `/api/config` 老实地把 `quota: {dailyLimit, used}` 报给前端，等于对外承诺一个不存在的限制
- `usage_daily` 表**没有 `visitor_id`**，按访客限额在现有表结构下根本算不出来
- 一个滥用者可以烧光全站当天的上游额度，而站方看不到是谁

### 任务

| ID | 任务 | 要求 |
| --- | --- | --- |
| T-151 | 新增 `visitor_usage(visitor_id, day, segments, chars, failures)` | 迁移 `0003`；主键 `(visitor_id, day)`；**只存数字，不存原文** |
| T-152 | `/api/translate` 入口配额拦截 | 超限返回 `QUOTA_EXCEEDED`（HTTP 429），`hint` 写清"明日 0 点恢复"与当前用量 |
| T-153 | 按访客限流 | `FR_RATE_LIMIT` 次/分钟，令牌桶或滑动窗口；超限 `RATE_LIMITED`（429）+ `Retry-After` |
| T-154 | 上游日消耗上限与降级 | 站点级 `FR_UPSTREAM_DAILY_CAP`（字符数）；触顶后**自动降级到免费线路**而不是直接拒绝 |

### 设计约束

- 访客身份来自已有的 `fr_vid` cookie（middleware 已下发，32 位 hex）
- 配额判断必须在**调用上游之前**，不能先花钱再拒绝
- 配额只算**实际送翻的段**，`skipped` 的空白段不计数
- 降级路径要能被用户看见：响应里带 `degraded: true` 与原因，前端显示"本站额度已用完，已切到免费线路"，**不是报错**
- 内存里做限流即可（单机部署），但重启后配额计数必须还在——配额读库，限流读内存
- 错误码 `QUOTA_EXCEEDED` 与 `RATE_LIMITED` **在 `internal/errs` 里已定义但没有任何构造函数，也没被用过**。
  补 `errs.QuotaExceeded()` / `errs.RateLimited(retryAfter)`，HTTP 429，同时补 `docs/01-architecture.md` 的错误码表。
  不要新造错误码。

### 出口标准

```
① 同一访客第 N+1 次请求返回 429 QUOTA_EXCEEDED，hint 含剩余与恢复时间
② 1 秒内连发 50 次，超出 FR_RATE_LIMIT 的请求被拒，且不打上游
③ 把 FR_UPSTREAM_DAILY_CAP 调到极小值，翻译仍成功但响应 degraded=true
④ 空白段不计入配额（同一请求里 3 空段 + 2 实段，只扣 2）
⑤ 重启服务后，当天已用配额不归零
⑥ 这些必须有自动化脚本验证，不能只靠手点
```

**出口不过，不进阶段 B。**

### 必须实现的六态（缺一个就算页面没做完）

| 态 | 怎么造 | 通过标准 |
| --- | --- | --- |
| 加载 | 网络限速 | 骨架屏，不是空白 |
| 空 | 新访客无词表 | 有说明 + 一个可点动作 |
| 失败 | 断开网关 | 原因 + 重试按钮 |
| 超时 | 网关指向黑洞地址 | 显示已等待秒数 + 取消 |
| 限额 | 日限额设 1 | 说明剩余与恢复时间，不报 500 |
| 未配置 | 清空 `FR_DEFAULT_MODEL` | 说明缺什么，不是白屏 |

### 关键交互约束

- 段落级隔离：一段失败只标红那一段，其余照常显示，**不整篇报错**
- `skipped:true` 的空白段不渲染译文、不标红、不给重试按钮
- 超长段（`TEXT_TOO_LONG`）**不给重试按钮**——重试永远不会成功，给"拆分段落"的提示
- 错误提示必须是可操作的：告诉用户"下一步做什么"，不是"服务内部错误"
- 不引入富文本编辑器。`textarea` + 自动增高就够，理由见 `docs/04-frontend.md`

### 出口标准

```
① 粘 5 段中文，Ctrl+Enter，5 段都出英文
② 断网翻 3 段，只有失败段标红，恢复网络重试成功
③ 手改一段译文，再点重译，弹确认
④ 清空模型配置，页面提示"本站未开启"，不白屏
⑤ 导出 Markdown，双语结构正确
⑥ 深浅色切换，逐页文字与边框都可读
```

## 6. 验证协议（每轮全量，不抽样）

### 没有模型密钥怎么办

**不要停下来等密钥。** 自己写一个本地假网关 `scripts/fake-gateway/`（Go 或 Node 均可），实现：

- `GET /v1/models` → 返回 `models.json` 里的模型清单
- `POST /v1/chat/completions` → 返回**确定性**的假译文与假纠错结果
- 可注入故障：`?fail=timeout`、`?fail=500`、`?fail=malformed`、`?fail=slow&ms=3000`

用它把 AI 路径全部验证一遍。**假网关只用于测试，不进生产镜像。**
拿到真密钥后再跑一遍"真模型冒烟"，覆盖 `provider: llm` 的真实输出质量。

### 每轮四步

```
① 全量走查   用户身份，F-01~F-20 逐项操作，留证据（截图/日志/curl 输出）
     ↓
② 提意见     只说"我在做 X 时，因为 Y，导致 Z"，不提方案
     ↓
③ 定级       产品归为 P0/P1/P2，写进本轮清单
     ↓
④ 修复+回归  开发按定级修，改完重跑全量，不能只跑改过的那项
```

### 角色纪律

- **用户**：真实写一篇博客，记录哪里难受。不许解释技术原因，不许提方案。
- **产品**：把"难受"翻译成问题条目并定级。不许替开发写代码。
- **开发**：按定级修复并回归。不许自行降级 P0，不许跳过。
- **用户视角的反馈必须发生在看代码之前。** 看过实现就会开始替它辩护。

### 定级标准

| 级别 | 定义 | 处理 |

| P0 | 硬门槛被破：要填 key、白屏、整篇失败、数据丢失 | 必须修完才能进下一轮 |
