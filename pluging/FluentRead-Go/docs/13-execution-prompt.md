# 13 · 执行提示词（交给 AI 的 goal 任务）

> 用法（两种模式，二选一）：
> - **全自动一次跑完（无人值守，挂机用这种）**：把「提示词全文」整段发给 AI（任务范围保持"全部分期"），并把会话设为自动执行/免确认权限模式。AI 从 P0 连续做到 P7，**中途不停、不等确认、不提问**；每期的走查单写完后立即继续下一期，全部完成后以 REPORT.md 收尾。你的走查（§十一 第 3–6 步）统一发生在它跑完之后，而不是卡在中间。
> - **分块交互执行（每块会停下等你确认，适合白天盯着做）**：同一份提示词把「任务范围」改成单期，例如 `任务范围：仅 P0`。注意：这种模式每完成一块就停——**不适合挂机**。
> - 新会话不需要其他上下文：规格在 `docs/11-rewrite-spec.md`，走查结论在 `docs/acceptance/`。

---

## 提示词全文

```text
# 任务：完整实现 FluentRead 写作台（Go + Gin + GORM + Vue 3）

## 你是谁、要做什么
你是本项目唯一的实现工程师，工作目录就是本仓库（FluentRead-Go）。你的目标：按规格把整个项目实现完并自验，交付一个能跑起来、能被真实用户逐项走查的完整版本。这不是 demo：规格里每一条 FR/NFR/AD 都要能打勾、有证据。

## 唯一规格（先通读再动手）
- docs/11-rewrite-spec.md —— 唯一实现依据。产品定位、FR 全集（每条带验收标准）、NFR 与六态、数据与隐私红线、系统架构、查词弹卡详细设计（§八）、分期规划（§十）、实施流程（§十一）、环境变量（附录 A）、错误码与用户文案（附录 B）都在里面。任何外部资料（包括你的既有记忆、其他文档、第三方博客）与它冲突时，一律以它为准。
- docs/10-requirements.md 是需求基线原文，仅供追溯；冲突处以 11 为准。
- 行为参考：本仓库现有 chi 版骨架（internal/ 下 translate/ratelimit/errs/store 的算法与语义可迁移，但必须按 Gin + GORM 重写，chi 路由代码不保留）。需要参考词卡触发/词书复习算法/ECDICT 链路细节时，可只读 ../FluentRead/src/features/selection-translation/、../FluentRead/src/features/vocabulary/、../FluentRead/web/wordDictionary.ts；禁止把 WXT、浏览器扩展 API、React 生态或其依赖引入本项目。

## 任务范围
全部分期：P0 → P1 → P1.5 → P2 → P3 → P3.5 → P4 → P5 → P5.5 → P6 → P7，按顺序执行，不许跳，每期出口标准（§十 表格最后一列）全部满足才能进入下一期。
（分块执行时此处改为：任务范围：仅 P<n>。）

## 每一期的工作循环
1. 实现：完成该期表格里的后端任务与前端任务，不扩范围。
2. 自检（以下命令必须真实执行，输出留证到 docs/acceptance/<期号>/evidence/）：
   - go vet ./... && go test ./...
   - CGO_ENABLED=0 go build -o bin/fluentread ./cmd/server
   - cd web && pnpm build（含 vue-tsc 类型检查）
   - 启动二进制，验证 GET /api/health 三态（ok / db / gateway）
   - 用 cmd/mockupstream（假 OpenAI 兼容上游，支持注入成功/失败/超时/超长/空响应）驱动 Playwright e2e 冒烟（web/e2e 已有脚手架），覆盖该期功能。
3. 对照该期出口标准，以用户操作方式逐条自测（真实点界面、真实发请求），不是只跑单测。
4. 产出 docs/acceptance/<期号>/WALKTHROUGH.md：用户走查单——每一步「操作 → 预期 → 你实测的结果」，六态每态一行证据。
5. 出口标准有任何一条不满足：继续修，修完重新走 2–4。不许带病进入下一期。

## 完成后的交付物（全部做完才算任务结束）
1. bin/fluentread：CGO_ENABLED=0 的单二进制，内嵌 web/dist；一条命令启动（默认 :8787）。
2. deploy/：Dockerfile + docker-compose.yml（app 必选，litellm 可选 profile）+ 部署说明。
3. docs/acceptance/：
   - FR-CHECKLIST.md —— 规格里每一条 FR/NFR/AD：验收标准、验证方法、证据（命令输出摘要/截图路径/接口响应）、结论。不许出现无证据的"已完成"。
   - 每期 WALKTHROUGH.md 与 evidence/。
   - KNOWN-ISSUES.md —— 遗留问题清单；P0/P1 必须为空，P2 允许并注明位置与复现步骤。
4. REPORT.md（仓库根目录）—— 交付报告：实现了什么、FR 覆盖情况、怎么一条命令启动、用户按什么顺序走查（从 docs/acceptance/P0/WALKTHROUGH.md 开始）。

## 硬规则（违反任何一条即视为任务失败）
1. 隐私红线（NFR-6 修订版）：整篇原文/译文与草稿一律不落库（只在浏览器 localStorage）；只有用户显式收藏（POST /api/words）与显式接受纠错才写 words/mistakes 表片段；usage_* 表只有数字。
2. 密钥纪律（FR-1002/FR-404）：一切密钥只存在于环境变量；/api/config 响应、日志、前端构建产物、测试夹具、提交内容中不得出现任何真实或示例密钥；自定义模型密钥即用即弃（no-store）。
3. 用户文案（NFR-11/附录 B）：禁用"上游、线路、配额、跳、回退、provider"等内部词；429 必须同时给 Retry-After 头和可读等待时间。
4. 错误码唯一出口：所有错误经 internal/errs 映射（附录 B），handler 禁止裸写 c.JSON(500, ...)。
5. 六态（§5.2）：任何页面的加载/空/失败/超时/限额/未配置缺一态，该页面不算完成。
6. 前端只允许 Vue 3 + Element Plus 一套组件库 + CSS 变量 token（DR-2）；出现第二套 UI 依赖即违规。
7. 模型名不写死在业务代码里（FR-407）；一切模型调用经 OpenAI 兼容网关协议（LiteLLM 或任意兼容端点）；MyMemory 降级线路 Go 直连实现、不经 LiteLLM（DR-10）。
8. 中文长注释：Go/Vue/TS/CSS 文件从第一个字符开始写文件头长注释（@file 路径、文件职责、主要内容、模块边界），职责变化时同步维护——规范见 ../FluentRead/docs/architecture.md 的「注释规范」一节。
9. 测试与构建不过不许提交；commit 信息注明期号与对应 FR（例：P2: FR-110 草稿持久化）。
10. 不升级依赖、不引入无关库；控制改动范围，不顺手重写无关代码。
11. 全自动、不中断：任何分期完成后不停止、不等待确认、不向用户提问，直接进入下一期；"停下"只发生在全部分期完成且交付物齐备之后（REPORT.md 写明"等待用户走查"）。用户走查（§十一 第 3、4 步）不属于你的职责，推迟到交付后由用户执行。
12. 不向用户提问：遇到规格未覆盖的小决策，按规格既有默认方案与惯例自行决定，记入 REPORT.md 的「自主决策记录」，继续干活；只有出现会导致大面积返工的根本性阻塞（如规格自相矛盾无法实现）才允许停止，并在 REPORT.md 顶部写清卡在哪、为什么。

## 隔夜执行的收尾
- 所有分期完成后：重跑一遍全量门禁与 e2e；确认 KNOWN-ISSUES.md 无 P0/P1；REPORT.md 置于仓库根目录。
- 天亮后用户将按 docs/acceptance/P0/WALKTHROUGH.md 开始逐块走查（§十一 第 3 步），你必须保证每一期都有可复现的走查单。
```

## 分块交互执行的会话节奏（对齐 11 号文档 §十一）

| 会话 | 提示词改动 | 会话结束时状态 |
| --- | --- | --- |
| 会话 1 | `任务范围：仅 P0` | 骨架可跑，P0 走查单就绪，等你走查 |
| 会话 2（你走查后） | `任务范围：仅 P1`（附上一块 ISSUES 若有 P2 遗留） | 翻译链路可用，等你走查 |
| 会话 3+ | 依次 P1.5 → P2 → P3 → P3.5 → P4 → P5 → P5.5 → P6 → P7 | 每块验收通过后再 /clear 进入下一块 |
| 收尾会话 | `任务范围：总验收`（跑全量门禁 + 更新 FR-CHECKLIST/KNOWN-ISSUES/REPORT） | 连续两轮 P0=0 且 P1=0 后项目结束 |
