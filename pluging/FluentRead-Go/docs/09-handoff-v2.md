## 一、目标

### 一句话

**把 FluentRead 浏览器扩展的能力，做成一个博客自带的网页。读者打开就能翻译、改译文、查术语，不装扩展、不注册、不配 API Key。**

### 两条硬门槛（不满足就是没做成）

| 门槛 | 判据 |
| --- | --- |
| 首次可用 | 读者打开站点到拿到第一段译文 **≤ 3 秒**，期间 **0 次配置操作** |
| 零配置 | 全站**不存在**"请填写 API Key"这类界面。访客不该知道 Key 是什么 |

### 判断标准（用来砍需求）

新功能如果不能加快"30 分钟写完一篇双语博客"，就不做。

### 明确不做

不是学习产品（不做背单词、复习调度、学习统计）；不是文档处理（不做 PDF/DOCX）；
不是多引擎评测；不是多租户 SaaS；不做管理后台页面（配置走 `.env` + LiteLLM UI）。

## 二、设计思路（每条都附理由，别只抄结论）

### 1. 为什么是"网站自带"而不是"让读者装扩展"

扩展的安装成本是**不可谈判的损耗**：一个只想看文章的读者，不会为了读你的博客去装一个插件。
所以能力必须长在页面上——这正是 Go 重写的全部理由。扩展版的代码只作交互参考，不作依赖。

### 2. 零配置靠"角色分层"，不是靠"不要配置"

三层，缺一层就会退化成"要访客自己填 Key"：

| 层 | 谁配 | 存在哪 | 访客感知 |
| --- | --- | --- | --- |
| L1 站点默认 | 站长 | 服务端 `.env` | 无感，这是主路径 |
| L2 站点模型池 | 站长 | `deploy/models.json` + 网关 | 顶栏一个下拉，可选 |
| L3 访客自带 | 访客 | 本机，**经 `/api/ai` 转发** | 默认不出现 |

**L3 必须走服务端转发**：浏览器直连第三方模型会被 CORS 拦死。所以要求不落盘、不写日志、
响应头 `no-store`，并在设置页如实告知"密钥会经本站转发"。这一点不能省，否则是欺骗用户。

#### 2.1 三方模型到底怎么接进来

这一条是历史需求里最容易在交接时丢掉的一条（"LiteLLM 必须上，要能接各种模型"）。
这里写死，别再靠口头传。

**客户端只认 OpenAI 兼容协议**：`POST {FR_GATEWAY_BASE}/v1/chat/completions`，
带 `Authorization: Bearer {FR_GATEWAY_KEY}`。所以"接三方"没有特殊适配层，
就是把 base 指过去、模型名用对方的名字。DeepSeek、OpenAI、通义、智谱、
Ollama、任何兼容端点，走的都是这一条路。

三种接法，按部署复杂度排：

| 接法 | 怎么配 | 适合 | 代价 |
| --- | --- | --- | --- |
| **A. 直连一家** | `.env` 里 `FR_GATEWAY_BASE=https://api.deepseek.com`、`FR_GATEWAY_KEY=sk-…`、`FR_DEFAULT_MODEL=deepseek-chat` | 只打算用一家 | 最小，**不用起 LiteLLM** |
| **B. 经 LiteLLM 挂多家** | `deploy/litellm.config.yaml` 的 `model_list` 加一条；`deploy/models.json` 加一条同名 | 想在多家之间切、要自动 fallback、要看用量 | 多一个容器 |
| **C. 访客自带 key** | 走 `/api/ai` 转发 | 高级访客 | **未实现**，见现状表 |

三条必须记住的约束：

1. **两份清单要一起改。** `models.json` 管"下拉里显示什么、标什么质量/速度/成本"，
   `litellm.config.yaml` 的 `model_list` 管"这个名字实际调到哪家"。
   只改一份的后果是**下拉里能选、一选就报错**，而且站长看不到任何提示，只能等访客来问。
2. **模型名不许写死在业务代码里。** 全部经请求的 `model` 参数传，服务端只校验
   "在清单里且 `enabled`"。加一家模型不该动 Go 代码，也不该重新发版前端。
3. **占位符不能直接启用。** `my-custom` 那条是模板（`openai/your-model-name` +
   `os.environ/CUSTOM_BASE`），启用前必须换成真实模型名和 base，否则访客选中必然失败。
   这类"下拉里摆着一个永远调不通的选项"，和之前 `features` 报 true 但端点不存在是同一类错误。

**实测结论**（2026-10-30）：把 `FR_GATEWAY_BASE` 指向任意 OpenAI 兼容端点，
在清单里加一个 `third-party-x` 并启用，`/api/config` 能下发、翻译能返回
`[third-party-x] …`、响应里 `provider=llm`、`model=third-party-x`。
即 A/B 两条路都是通的，缺的只有 C。

### 3. 为什么分段，而不是整篇一次翻

三个理由，按重要性排：

1. **失败隔离**：一段挂了不能拖垮整篇。整篇一次翻，网关抖一下你就得重来。
2. **可编辑**：作者要能单独改某一段的译文，整篇一个字符串做不到。
3. **可计费**：按段计配额，空行不计费，账才对得上。

配套的三条约定（都踩过坑）：

- **空段是 `skipped`，不是错误**。粘贴整篇时空行会变成空段，返回 `ok:true, skipped:true`，不打上游、不计配额。
- **超长段报 `TEXT_TOO_LONG`，不给重试按钮**。永远重试不成功的操作给按钮，就是在骗用户点。
- **`style` 拼错回落默认值并 WARN**。`data-fr-style` 是站长手写的，拼错不该让整站失效。

### 4. 为什么"降级"不等于"报错"

付费线路日消耗到上限时，**继续返回 200**，带 `degraded:true` 和原因，自动切免费线路。
理由：读者要的是"能读"，不是"知道站长超支了"。但同时必须让站长看得见——
所以降级要进日志、要进 `/api/config`，否则就是"访客觉得译文变差，站长零感知"。

### 5. 为什么是"六态"而不是"能跑就行"

加载 / 空 / 失败 / 超时 / 限额 / 未配置。**缺一态算没做完。**
六态是最容易糊弄的地方：只做 happy path，演示时一切正常，真实用户第一次遇到网关超时就看见白屏。

### 6. 为什么验证必须是"页面走查"，不是 bash 断言

这是最重要的一条，也是上一轮返工的原因。

- **bash 脚本只能证明"接口返回了 200"**，证明不了"用户看得懂、点得动、找得到"。
  写一百条 `curl | grep` 也看不出两栏错位、看不出"0.0s"像坏了、看不出术语加了没生效。
- **脚本的角色只有一个：把环境准备好**（起假网关、起后端、编译前端），然后交给浏览器。
- **判断必须发生在页面上**：打开、粘贴、点按钮、滚动、悬停、切深色、缩到 400px。
  看到的每一处别扭都记下来，写成"我在做 X 时，因为 Y，导致 Z"，**不写解决方案**。

写脚本验证体验，等于用体温计量血压。

### 7. 为什么三个角色不能混

| 角色 | 只做 | 禁止 |
| --- | --- | --- |
| 用户 | 记录"做 X 时因为 Y 导致 Z" | 提方案、读代码 |
| 产品 | 定级 P0/P1/P2 | 直接改代码 |
| 开发 | 按定级修 | 自己给自己定级 |

**用户视角的反馈必须在读代码之前产生**。先看代码再"体验"，看到的全是自己想看的东西。

### 8. 为什么要有假网关

没有模型密钥时不能停下来等，否则整条链路永远验不了。
`scripts/fake-gateway/` 实现 OpenAI 兼容的 `/v1/models`、`/v1/chat/completions`，
外加 MyMemory 兼容的 `/get`，支持故障注入（`?fail=timeout|500|malformed|slow`）和调用计数（`/__stats`）。

两个设计细节，都是被坑出来的：

- 假译文末尾附 `§<原文指纹>-<系统提示词指纹>`。模板池只有 12 句，不同段落很容易撞同一句，
  撞了以后"第 N 段的译文是不是第 N 段的"就验不出来。系统提示词的指纹顺带证明"术语确实被送到了上游"。
- `/__stats` 记调用次数。**只看响应码无法证明"超限时没打上游"**，必须看计数。

### 9. 停止条件

跑满 6 轮（R0–R5）**且**连续两轮 P0=0 且 P1=0。不许为了收工把 P0 降级成 P1。

### 已修的真实缺陷（都值得知道，避免重新踩）

1. 空段导致整批 400 → 改 `skipped:true`。
2. 超长段被 MyMemory 报成"已限流" → 拆出 `TEXT_TOO_LONG`，避免给永远失败的重试按钮。
3. `/api/config` 没配密钥仍下发模型清单 → 前端永远进不了"本站未开启"态。
4. 配了密钥忘配 `FR_DEFAULT_MODEL` → 每次请求先打一次必然失败的付费调用再静默降级。
5. 客户端断开后用量写库失败（`context canceled`）→ 等于给"断连"留了免费通道。改 `context.WithoutCancel`。
6. 设置页说"纠错已开启"，写作台说"P3 阶段开放" → 同一功能两套话。
7. `features.dictionary` / `visitorModel` 报 true 但端点不存在 → 改为 false。
8. 刷新丢整篇草稿（P0）→ localStorage + 防抖 + `pagehide` flush。
9. 粘贴时空行变空输入框，段号跳号 → 只在粘贴路径丢空段。
10. 两栏行高不同步 → 改成单一 grid，每段一行。
11. **失败提示把内部线路名说给读者**（"免费翻译线路不可达"）→ 上游错误一律只回
    "翻译服务暂时不可用，请稍后重试"，线路细节进日志，且一次请求只记一条。
    这条值得记住：错误信息泄露内部结构，比错误本身更让人困惑。

你接手 FluentRead-Go：一个 Go + Vue 的博客翻译站。先读这三份文件，别急着写代码：

  docs/06-plan.md            ← 阶段与出口标准
  docs/07-verification.md    ← R 轮次协议

## 你的任务

1. 先跑通现有门禁，确认基线是绿的：
     make build
     NODE_OPTIONS= ./scripts/verify-p1.sh
     NODE_OPTIONS= ./scripts/verify-p1.5.sh
     NODE_OPTIONS= ./scripts/verify-p2.sh
   三个都必须全过。有一个红，先修它，别往下做。

2. 接着做 R4：修 R3 留下的两条 P2（见 docs/evidence/R3/report.md）——
   R3-02 表头段数与空段框数不一致，R3-03 窄屏顶栏吃掉首屏。
   都是 P2，别顺手改大；改完必须重跑三道门禁 + R0 走查。

3. R4 做完做 R5：全量重走一遍，确认没有回归。

4. 连续两轮 P0=0 且 P1=0 之后，才允许开 P3 纠错。

## 硬性要求

- **不许用 bash 断言代替页面走查。** 你要"看"页面：截图、滚动、悬停、缩放。
  接口 200 不代表用户看得懂。
- **不许为收工把 P0 降级成 P1。** 定级只看"会不会让人放弃使用"，不看"改起来麻不麻烦"。
- **用户视角的观察必须在读代码之前产生。** 先看代码再体验，看到的全是自己想看的东西。
- **一条观察的格式**：「我在做 X 时，因为 Y，导致 Z」。不写解决方案。
- **不许给永远重试不成功的操作加"重试"按钮**（超长段、配额用尽、语言不支持）。
- **降级不是错误。** 上游额度用完时返回 200 + degraded:true，不是 5xx。
- **空段不是错误。** 返回 ok:true, skipped:true，不打上游、不计配额。
- **加模型只改两份配置**：`deploy/models.json`（下拉显示什么）+
  `deploy/litellm.config.yaml` 的 `model_list`（这个名字实际调到哪家）。
  **不许把模型名写死进 Go 代码**。只改一份的后果是"下拉能选、一选就报错"，站长还看不到提示。
  别启用 `my-custom` 这种占位符——那等于在界面上摆一个永远调不通的选项。

## 环境坑（本机，踩过多次）

1. 配置变量是 `FR_` 前缀：`FR_ADDR` / `FR_DB_PATH` / `FR_GATEWAY_KEY` / `FR_DEFAULT_MODEL`。
   写裸 `PORT` 会静默回落到 `:8080`，而本机 8080 被别的服务占着，
   表现是"日志看着正常但服务没起来"。
2. curl 打本机必须加 `--noproxy '*'`（环境有 HTTP_PROXY）。
3. 本机 `NODE_OPTIONS` 注入了一个 safe-delete 钩子：
   - vite 清 `dist`、Playwright 清证据目录会被拦（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）；
   - SQLite 建/删 journal 也会失败，日志里是 `disk I/O error (2570)`，**看着像数据库 bug，其实不是**。
   跑任何验证前先 `NODE_OPTIONS=`。
4. 在 `\` 续行的 env 赋值和命令之间**不要插注释**，续行会把注释接到命令上，整条 env 前缀失效，
   报出来的却是"浏览器不存在"这种完全无关的错。
5. 构建顺序：**先 `make web` 再 `make build`**。`go:embed` 在编译时把 `web/dist` 打进二进制，
   顺序反了就嵌入空目录，页面打开是 404。
6. Playwright 浏览器版本对不上时，用缓存里已有的 headless shell，
   不要 `npx playwright install`（内网可能下不动）。
