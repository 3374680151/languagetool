# 10 · 需求规格（可直接交付开发）

> 这份文档只回答一个问题：**这个东西必须做到什么，才算做对了。**
> 不谈怎么实现、不谈进度。开发照这份做完，验收照这份逐条打勾。
>
> 每一条需求都带「验收标准」——写不出验收标准的需求，等于没提。

---

## 〇、需求变更记录

**2026-10-31 修正核心方向。** 此前文档把主场景写成"粘贴中文草稿 → 翻成英文"，
方向反了。真实需求是：

> **作者用英文写博客，左边写英文，右边实时看中文回译；同时检查单词与语法；
> 模型可以默认用，也可以自己配。**

这不是措辞问题，是产品定位问题，连带三处要改：

| 项 | 之前（错） | 现在（对） |
| --- | --- | --- |
| 默认语言对 | 中 → 英 | **英 → 中** |
| 译文的作用 | 产出物（发出去给人读） | **回译校验**（确认英文表达的是我想说的） |
| 纠错的位置 | P3 附属功能 | **核心功能**，与翻译并列 |

读者侧（打开博客直接读、选中查词）仍然要做，但它是**第二场景**，不是主线。

---

## 一、目标与边界

### 1.1 一句话

给**用英文写作的中文作者**一个写作台：左边写英文，右边即时看到中文回译，
写错的地方（单词、语法）被指出来，改完导出就能发。

### 1.2 两条硬门槛

| 编号 | 门槛 | 怎么量 |
| --- | --- | --- |
| G-1 | 首次可用 | 打开写作台到拿到第一段中文回译 **≤ 3 秒**，期间 **0 次配置操作** |
| G-2 | 零配置 | 默认模型开箱即用；全站**不存在**"请填写 API Key"这种拦路界面 |

### 1.3 判断标准（用来砍需求）

新功能如果不能加快「写完一篇英文博客并确认没写错」，就不做。

### 1.4 明确不做

| 不做 | 原因 |
| --- | --- |
| 学习产品形态（背单词、复习调度、学习统计） | 作者要的是写对，不是考试 |
| 文档处理（PDF / DOCX / 整页对照） | 不是博客场景 |
| 多引擎评测、翻译质量打分 | 对写作者没有直接价值 |
| 多租户 SaaS、账号体系 | 个人站点，匿名即可 |
| 站长管理后台页面 | 配置走环境变量 + 网关 UI |
| 富文本编辑器 | 段落级替换会和富文本内部模型打架 |

## 二、角色与场景

### 2.1 角色

| 角色 | 是谁 | 关心什么 |
| --- | --- | --- |
| **作者**（主） | 你，用英文写博客的中文作者 | 写对、改快、发出去 |
| 读者（次） | 打开博客的人 | 看懂英文，或看中文对照 |
| 站长 | 部署这套东西的人 | 别超支、别被刷、别挂 |

### 2.2 主场景：写一篇英文博客

1. 打开写作台，**左边英文、右边中文**（默认英 → 中，不用选）
2. 写一段英文 → 按 `Ctrl/⌘ + Enter` → 右边出中文回译
3. 看中文：如果中文意思跟我原来想的不一样，说明英文写歧义了 → 回去改英文
4. 点"纠错"：单词拼错、用词不当、语法问题逐条列出来 → 逐条接受或忽略
5. 专有名词加进术语表，保证全文一致
6. 导出 Markdown（英文 / 中英对照）→ 发布

### 2.3 次场景：读者读一篇英文博客

打开页面 → 选中段落或点击"翻译" → 看到中文 → 选中生词看释义。

## 三、功能需求

> 编号规则：`FR-<模块><序号>`。每条都写清「必须怎样」和「怎么算做到」。

### 3.1 写作台布局与输入（FR-1）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-101 | **左英右中**双栏对照，默认语言对 **英 → 中** | 首次打开，左边标签"English"、右边"中文"，不需要手动选语言 |
| FR-102 | 左右两栏**逐行对齐**，任一行左右顶端偏差 ≤ 2px | 20 段文档逐行量顶端坐标，最大差 0px |
| FR-103 | 长文滚动后仍能确认"这段中文属于哪段英文" | 悬停某行，左右两格同时高亮；段号连续可见 |
| FR-104 | 按空行自动分段；粘贴整篇英文自动切开 | 粘贴 4 段 + 3 空行，得到 **4** 个输入框，段号 1/2/3/4 不跳号 |
| FR-105 | 粘贴时空行**不**变成空输入框；手动按两次回车仍能开新段 | 两种情况分别验证 |
| FR-106 | `Ctrl/⌘ + Enter` 全译；`Ctrl/⌘ + Shift + Enter` 只译光标所在段 | 两个快捷键都生效，不触发浏览器默认行为 |
| FR-107 | 每段独立状态：待译 / 翻译中 / 完成 / 失败 | 一段失败，其余段仍正常出结果 |
| FR-108 | 右边中文**可直接编辑**，不需要点"编辑" | 点击即可改，无弹窗 |
| FR-109 | 单段重译；**手改过的段重译前必须确认一次** | 未手改 → 直接重译；手改过 → 弹确认，可取消 |
| FR-110 | 刷新不丢稿：英文原文、中文回译、手改、术语都要还在 | F5 后段落数、首段文字、译文数量与刷新前一致 |
| FR-111 | 空文档时给说明 + 一个可点的动作（载入示例） | 首次进入不白屏，示例可一键载入 |
| FR-112 | 语言对可改（英→中 / 中→英 / 其他），但**默认永远是英→中** | 改过之后本机记住，新访客仍是英→中 |

### 3.2 纠错（FR-2，核心功能）

> 写英文的人最需要的是"哪里写错了"，不是"再翻一遍"。这条和翻译同级，不是附属。

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-201 | **单词级纠错**：拼写错误、用词不当（word choice）、单复数 | 一段里故意写 2 个拼写错 + 1 个用词不当，全部被指出 |
| FR-202 | **语法级纠错**：主谓一致、时态、冠词、介词、句子结构 | 一段里故意写 3 处语法错，全部被指出 |
| FR-203 | 每条建议包含：**原文片段 → 建议改法 → 类别 → 理由** | 4 个字段齐全；类别属于拼写/语法/标点/风格/用词 |
| FR-204 | **`original` 必须是原文子串**，否则丢弃（不让模型算偏移量） | 模型返回不存在的片段时，该条被丢弃且不报错 |
| FR-205 | 逐条接受/忽略，接受后重新校验剩余条目的位置 | 接受第 1 条后，第 2/3 条仍能正确定位 |
| FR-206 | 只检查**英文段落**，中文段落跳过 | 中文段没有纠错入口 |
| FR-207 | **不自动跑**，必须手动触发（写的时候不要打断思路） | 输入过程中不弹任何建议 |
| FR-208 | **不做整段重写**，只给逐条建议 | 界面不出现"一键改写全文" |
| FR-209 | 没有错误时明确说"这段没有发现问题"，不是空白 | 正确段落点纠错，有明确反馈 |

### 3.3 翻译 / 回译（FR-3）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-301 | 默认英 → 中；支持自动检测、简中、繁中、英、日、韩、法、德、西、俄 | 非法语言码返回 400 + "语言不受支持"，不返回 500 |
| FR-302 | 支持风格：academic / formal / concise / casual，默认 academic | 风格拼错**不报错**，回落默认值并记 WARN |
| FR-303 | **段落级隔离**：一段失败不影响其他段 | 3 段中 1 段故意失败，另 2 段必须成功 |
| FR-304 | **空白段不算错误**：返回 `ok:true, skipped:true`，不打上游、不计配额 | 5 段请求含 3 空段，响应里 3 段 skipped，配额只扣 2 |
| FR-305 | **超长段单独报错**：单段 > 5000 字 / 合计 > 20000 字 / 单次 > 20 段 | 返回 `TEXT_TOO_LONG` + "请拆分第 N 段"；**不给重试按钮**（重试永远不会成功） |
| FR-306 | **降级不是错误**：付费线路日上限触顶时切免费线路，仍返回 200 | 响应带 `degraded:true` + 原因，译文可用 |
| FR-307 | 错误文案**不暴露内部结构**：不提"免费线路""付费线路""第几跳" | 网关 500 时用户只看到"翻译服务暂时不可用，请稍后重试" |
| FR-308 | 失败原因必须可行动：说清"等多久""该做什么" | 配额用尽要说剩余与恢复时间；超长要说拆分 |

### 3.4 模型选择（FR-4）

> 需求原话："可以自选默认的，还是自己配置模型，自定义的这种。"

三个层次，**默认层必须开箱即用**，后两层是可选增强：

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-401 | **默认模型**：站长配好，作者打开就能用，不需要选 | 全新浏览器打开，直接能翻译 |
| FR-402 | **站点模型池**：站长可开多个模型，作者在顶栏下拉里选 | 清单里 `enabled:true` 的出现在下拉，带质量/速度/成本标签 |
| FR-403 | **自定义模型**：作者可自己填 `baseURL + Key + 模型名`，用自己的账号 | 填完能"测试连接"并翻译成功；不填则不影响默认模型 |
| FR-404 | 自定义模型**经服务端转发**（浏览器直连会被 CORS 拦） | 密钥不落盘、不写日志、响应 `no-store`；设置页如实告知"密钥会经本站转发" |
| FR-405 | 自定义模型失败时**自动回落默认模型**并提示 | 填错 key → 提示"自定义模型不可用，已用默认模型" |
| FR-406 | **支持任意 OpenAI 兼容的三方端点**：DeepSeek / OpenAI / 通义 / 智谱 / Gemini / Ollama / 自建 | 把 base 指向该端点、模型名用对方的，即可翻译成功 |
| FR-407 | 模型名不许写死在业务代码里 | 加一家模型不改代码、不发前端版 |
| FR-408 | **两份清单必须一致**：`models.json`（显示什么）与网关 `model_list`（实际调哪家） | 只改一份时系统要能报警，不能等用户报错 |
| FR-409 | 下拉里**不许出现调不通的占位模型** | `my-custom` 这类模板默认 `enabled:false`，启用前必须填真实值 |

### 3.5 术语（FR-5）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-501 | 可增删改术语（英文原文 → 指定中文译法），站点级共享 | 加一条"recall → 召回率"，列表可见 |
| FR-502 | 术语必须**真的进提示词**，不是只在界面上显示 | 改术语后重译，模型收到的 system prompt 发生变化（可用指纹验证） |
| FR-503 | 术语改了但没重译时，必须提示"当前译文是旧的"，并给一键重译 | 出现横幅；点"全部重译"后提示消失 |
| FR-504 | 一键重译遇到手改段要先确认 | 有手改 → 弹确认；无 → 直接重译 |
| FR-505 | 术语冲突按「站点 > 用户 > 默认」消解 | 同一术语两处定义，以更高优先级为准 |

### 3.6 配额与限流（FR-6）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-601 | 按访客计日配额，**落库**，重启不归零 | 用满后重启，仍返回 429 |
| FR-602 | 按访客 + 来源 IP 双桶限流（内存即可，重启清零可接受） | 连发 50 次，放行数 = 配额数，被拒请求**一次都没打上游** |
| FR-603 | 站点级付费上游日字符上限，触顶**降级**不拒绝 | 见 FR-306 |
| FR-604 | **计费口径**：按段计，空白段不计；上游消耗只算付费线路成功的字符 | 5 段含 3 空段 → 扣 2 段；免费线路成功不计上游消耗 |
| FR-605 | 429 必须同时给 `Retry-After` 头（给程序）和可读提示（给人） | 响应头与 body 都有等待时间 |
| FR-606 | 额度只在快用完时提示，不要常驻顶栏 | 剩余充足时顶栏无额度文字 |

## 四、非功能需求

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| NFR-1 | 首段回译 ≤ 3 秒（本机假网关下 ≤ 1 秒） | 走查计时 |
| NFR-2 | 25 段长文全译 ≤ 10 秒，页面不卡死 | 走查计时 + 滚动流畅 |
| NFR-3 | 前端不引 UI 框架，样式用 CSS 变量统一 | 构建产物无框架运行时 |
| NFR-4 | 单二进制部署：前端 `go:embed` 打进 Go 程序 | 一个进程 + 一个 SQLite 文件即可跑 |
| NFR-5 | 数据库纯 Go 驱动（无 CGO） | `CGO_ENABLED=0` 能编译 |
| NFR-6 | **隐私红线：不存原文、不存译文**，用量只记数字 | 查库，`usage_*` 表里没有正文 |
| NFR-7 | 日志不记正文，只记长度、耗时、错误码 | 抽查日志 |
| NFR-8 | 六态齐全（见第五节），缺一态算未完成 | 逐态截图 |
| NFR-9 | 深色模式文字与边框都可读（对比度 ≥ 4.5:1） | 逐页测量 |
| NFR-10 | 400px 窄屏可用，顶栏不溢出、不占掉首屏 | 窄屏截图 |
| NFR-11 | 文案说人话：不出现"上游""线路""配额"这类内部词 | 通读所有用户可见文案 |

## 五、六态要求

任何页面在任何时刻都必须处于这六种状态之一，且每种都有明确界面。**缺一态算没做完。**

| 状态 | 触发 | 界面要求 |
| --- | --- | --- |
| 加载 | 请求中 | 骨架屏，不是空白，不是转圈 |
| 空 | 没有内容 | 说明 + 一个可点的动作 |
| 失败 | 请求失败 | 原因 + 下一步；能重试的给按钮，不能的说明为什么 |
| 超时 | 上游太慢 | 显示已等待秒数 + 取消 |
| 限额 | 配额用尽 | 剩余量 + 恢复时间，**不报 500** |
| 未配置 | 站点没配模型 | 说清缺什么，页面照常可用，不白屏 |

## 六、数据与隐私

| 项 | 要求 |
| --- | --- |
| 访客身份 | 匿名 cookie，无需注册 |

## 七、验收标准

### 7.1 功能验收

逐条打勾第三节所有 FR。每条都要有可复现的操作步骤和预期结果，不接受"应该可以"。

### 7.2 体验验收（每个阶段必做）

以**真实作者身份**在页面上走一遍，不是跑脚本断言：

1. 打开写作台 → 直接写一段英文（不要粘贴中文）
2. 全译 → 看中文是否对得上我想表达的意思
3. 点纠错 → 逐条看建议是否靠谱、是否定位准确
4. 加术语 → 重译 → 确认术语生效
5. 刷新 → 关掉重开 → 换深色 → 缩到 400px
6. 制造失败（断网 / 网关卡住）看提示是否说得清
7. 记下每一处别扭，写成「我在做 X 时，因为 Y，导致 Z」，**不写解决方案**

定级只看一件事：**会不会让人放弃使用**。

| 级别 | 判据 |
| --- | --- |
| P0 | 会让人直接放弃（丢数据、白屏、核心功能不可用） |
| P1 | 每次用都会遇到，且明显影响效率 |
| P2 | 不影响做事，但看着不对/多余 |

### 7.3 收工条件

至少 6 轮体验迭代，**且连续两轮 P0=0 且 P1=0**。
不许为了收工把 P0 降级成 P1。
