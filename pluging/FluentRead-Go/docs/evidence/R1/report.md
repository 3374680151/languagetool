## R1-01 两栏对齐

**问题**：原来左右是两个独立的滚动列表，行高只能靠"内容刚好一样长"碰运气。
右边译文普遍比左边原文短，滚到第 3 段以后两边错开小半屏。

**改法**：`SplitPane.vue` 从"两个列表"改成单一 grid。每段一行 `.split-row`，
用 `display: contents` 让行内两格直接落进第 1、2 列，行高由行内较高者决定；
分隔条改成绝对定位的覆盖层，不随内容滚走；窄屏退回逐段上下堆叠。
`WriteView.vue` 相应改成"表头行 + 每段一行"。

**验证**：走查里逐行量左右两格 `getBoundingClientRect().top` 的差值。

```
每行左右顶端的最大偏移 0px（期望 0；>2px 就是要来回找对应关系）
每行偏移: 0, 0, 0, 0px
```

## R1-02 术语生效

**问题**：加完术语再按 `Ctrl+Enter`，界面只说"没有需要翻译的段落"——因为所有段都是
`done` 状态，没有"待翻"的段。用户无法判断术语生效了没有，也没有入口让它生效。

**改法**：

- `doc.ts` 记 `glossarySig`（上次成功翻译时的术语签名），与当前术语比对得出 `glossaryStale`；
  仅当"有已完成的译文"且"签名不一致"时为真。
- `WriteView.vue` 据此亮横幅："术语表改过了，当前译文还是旧的"，带一个"全部重译"。
- `retranslateAll()` 强制重跑全部段落；**有人手改过就先确认一次**，
  否则一键重译等于把作者的修改吃掉。

**验证**（这是这一轮最关键的一条）：光看"几段译文变了"是弱证据——重译本身也可能让文本抖动。
所以让假网关把**系统提示词的指纹**也附在译文末尾，直接看 prompt 有没有变：

```
加完术语按 Ctrl+Enter：出现"术语表改过了，当前译文还是旧的"提示
点"全部重译"后 4 段译文发生变化，旧术语提示已消失；系统提示词指纹 2f03df → d84a12（术语确实进了 prompt）
```

指纹从 `2f03df` 变成 `d84a12`，说明术语真的进了送上游的 system prompt，
而不只是界面上换了个提示。

## 本轮修掉的验证基础设施问题

这两个都不在计划里，但不修的话"通过"是假的：

1. **指纹测量写错了**。走查里判断"第 N 段的译文是不是第 N 段的"，用的是
   `t.slice(-8)`，而假译文末尾是 `§<原文指纹>-<系统提示词指纹>`（15 字符），
   截最后 8 位只剩用户指纹的**最后 1 个字符**——16 分之一的碰撞率，4 段撞一次很正常。
   于是"索引错位"和"哈希撞车"在报告里长得一模一样，第一次跑就报了
   "4 段只有 3 个不同指纹"，差点被当成产品 bug 去查。改成从 `§` 起整段截取，
   并把"原文指纹是否互不相同"和"系统提示词指纹是否只有一种"分开看。

2. **报告被自己的脚本删了**。`EVIDENCE_DIR` 同时是 Playwright 的 `outputDir`，
   每次开跑前会被清空。R0 的 `report.md` 和截图放同一层，R1 回归重跑一次就没了，
   证据目录里只剩截图，看起来像"从没写过报告"。现在截图落 `shots/` 子目录，
   报告留在外层。
