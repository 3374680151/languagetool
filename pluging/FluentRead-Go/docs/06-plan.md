# 实施规划

七个阶段，顺序不可打乱：**每个阶段的出口标准不过，不进下一阶段。**

---

## 阶段总览

| 阶段 | 目标 | 出口标准 |
| --- | --- | --- |
| **P0 骨架** | 能启动、能连库、能探活 | `curl /api/health` 返回 `ok:true` |
| **P1 翻译链路** | 服务端能真翻 | `curl /api/translate` 返回真实译文，模型清单来自网关 |
| **P1.5 护栏** | 能安全地给陌生人用 | 超限返回 `QUOTA_EXCEEDED`，上游日消耗有上限 |
| **P2 写作台** | 能看见、能操作 | 浏览器里粘中文出英文，可编辑可导出 |
| **P3 纠错** | 能逐条改 | 一段烂英文能出问题列表，接受后原文被替换 |
| **P4 词典与术语** | 能查、能锁 | 选词出词卡；术语命中后译文遵循 |
| **P5 词表** | 能存、能找 | 收藏后 `/learn` 可见，可搜索可导出 |
| **P6 SDK** | 博客能用 | 任意页面加一行 script 能划词 |
| **P7 部署** | 上服务器 | 一条 compose 命令起，公网可访问 |

| T-106 | `GET /api/config` | 模型清单、语言、feature 开关 |
| T-107 | `usage_daily` 累加 | 只记数字 |

**出口**：`curl /api/translate` 一次翻 3 段，其中 1 段故意造错也能返回另外 2 段的成功结果。

**已达成**，回归脚本 `scripts/verify-p1.sh`（起临时端口、跑断言、自动收尾），覆盖：

- 4 段请求里 2 段成功、1 段空白跳过、1 段真实失败（超免费线路上限），失败段不拖累其他段；
- `from=auto` 无模型密钥时给出可操作提示，而不是"服务内部错误"；
- 非法语言码走统一错误体；`/api/config` 不含任何密钥；
- `usage_daily` 只落数字，`chars` 与段数分别累计。

验证中修掉的真实缺陷：空段落曾导致整批 400（与"不做整批失败"矛盾）、
超长段被误报成"已限流"（前端会给出永远重试不成功的按钮）。

## P1.5 公开前的护栏 ✅

P1 跑通只说明"能翻"，不说明"可以给陌生人用"。以下三项不做，公开即失控。

| ID | 任务 | 说明 | 状态 |
| --- | --- | --- | --- |
| T-151 | `visitor_usage(visitor_id, day, segments, chars, failures)` | 迁移 `0003`；`usage_daily` 另加 `upstream_chars`（`0004`） | ✅ |
| T-152 | `/api/translate` 入口配额拦截 | 超限 429 `QUOTA_EXCEEDED`，hint 含已用/剩余/恢复时间 | ✅ |
| T-153 | 按访客限流 | 令牌桶，`FR_RATE_LIMIT` 次/分钟，429 + `Retry-After` | ✅ |
| T-154 | 站点级上游日消耗上限 | `FR_UPSTREAM_DAILY_CAP` 字符数，触顶降级到免费线路，响应带 `degraded` | ✅ |

**出口**：同一访客第 N+1 次超限请求返回 `QUOTA_EXCEEDED`，且全站上游日消耗有上限。

**已达成**，回归脚本 `scripts/verify-p1.5.sh`（起假网关 + 每条独立数据库 + 自动收尾），
对应出口标准 ①~⑥：

| # | 断言 | 实测 |
| --- | --- | --- |
| ① | quota=2，第 2 次请求 429 `QUOTA_EXCEEDED`，hint 含"剩余 0 段 / 约 10 小时后恢复" | PASS |
| ② | rate=10，0.64 秒内连发 50 次 → 200×10、429×40，付费上游调用数正好 10 | PASS |
| ③ | cap=5 字符 → 200 + `degraded:true` + `provider:mymemory`，付费上游调用 0 次 | PASS |
| ④ | 3 空段 + 2 实段 → `visitor_usage.segments=2`、`usage_daily.requests=2` | PASS |
| ⑤ | 重启后 `/api/config.quota.used` 仍为 2，再请求继续 429 | PASS |
| ⑥ | 以上全部由脚本断言，无人工点击 | PASS |

"不打上游"用假网关的 `/__stats` 计数证明——只看响应码证明不了上游没被调用。

验证中修掉的真实缺陷：

- 熔断判据用"已消耗 >= 上限"时，上限设成极小值第一次请求仍会打付费线路，
  与"触顶即降级"矛盾；改成"已消耗 + 本次字符数 > 上限"。
- 用 `usage_daily.chars`（含免费线路）做熔断会让免费流量误触发降级；
  单开 `upstream_chars` 列，只统计付费消耗。

两条实现要点（都不是"界面加个提示"那么简单）：

- **对齐**：原来的做法是两个独立滚动列表，行高只能靠"内容一样长"碰运气。改成单一 grid，
  `.split-row { display: contents }` 让每行的左右两格直接落进两列，行高由行内较高者决定，
  分隔条改为绝对定位覆盖层，不随内容滚走。窄屏退回逐段上下堆叠。
- **术语**：`doc.ts` 记下"上次成功翻译时的术语签名"，与当前术语比对得出 `glossaryStale`；
  有译文且签名不一致才亮横幅。重译走 `retranslateAll()`，有人手改过就先确认一次，
  否则直接覆盖等于把作者的修改吃掉。

**R1 出口**：P0=0、P1=0 ✅。但这只是第一轮清零，按 `docs/07-verification.md` 还要

| 编号 | 任务 | 说明 | 结果 |
| --- | --- | --- | --- |
| R0-07 | 顶栏额度噪音 | 额度充足时（剩余 > max(10, 10%)）不显示"今日剩余 N/M 段"；无限额度时完全不显示 | `TopBar.vue` 已改：只在低额度时预警 |
| R0-08 | 译文对应弱 | 长文滚动后无法确认"这段译文属于哪段原文" | `SplitPane.vue` 已加：鼠标悬停一整行时，左右两格同时高亮 `var(--surface-2)` |

两条都是两三千字短文感知不强、但**长文场景下必须有的**细节：

- **额度降噪**：用户是来写博客的，不是来管配额的。原来顶栏一直挂着
  `今日剩余 1000/1000 段`，对 99% 的使用时间是纯噪音。改成只在剩余 <= max(10, 日上限10%) 时显示，
  且带 warn 色提醒。无限额度时彻底消失。
- **悬停高亮**：原来只有 6px 小圆点做状态指示，滚动后对应关系全靠数段号。
  现在在 `.split-row:hover` 时给左右两个网格单元格同时铺 `var(--surface-2)` 背景，
  0.1s 过渡，鼠标划到哪行，哪行就亮起来，对应关系一目了然。

**R2 出口**：本轮没有新 P0/P1。上一轮（R1）已清零，本轮也没有新增，
连续两轮 P0=0 且 P1=0 ✅。按 `docs/07-verification.md`，至少还要再跑 R3–R5。
