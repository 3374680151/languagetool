2. 写作到纠错的完整流程

1
写。直接在编辑区打字或粘贴。停止输入约 0.7 秒后自动检查，不用点按钮。
2
看。问题词出现下划线，页头徽章显示「N 个问题」，右侧同步出卡片。
3
改。点带下划线的词 → 纠错卡贴在那个词旁边弹出 → 点建议（第一个是推荐值，实心高亮）。改完自动跳到下一处。
4
收。遇到专有名词/生词就点「收藏」，词进词库且不再报拼写错误；不想改就「跳过」（可恢复）或「永久忽略」（不再提示）。
5
交。复制 / 下载 .txt / 导出 Markdown 报告。全部应用前会先给你看 diff 清单。
要点：改错发生在错误所在的位置。右侧清单只用来扫读和批量处理，不是唯一入口。

3. 纠错弹窗逐个按钮

元素作用

‹ ›上一条 / 下一条（Alt+← / →）
跳过这条先不改，也不算忽略；右侧出现「已跳过 N 条」，可一键恢复
收藏加入词库并进入拼写白名单。点完弹窗内直接变成「✓ 已收藏」，下方展开备注输入框，不跳走
永久忽略把这条规则写进 disabledRules，以后都不提示（存在浏览器里）

4. 我的词库

三个收藏入口

  • 正文里选中任意词/短语 → 浮出「＋ 收藏『xxx』」
  • 纠错弹窗里点「收藏」（收藏被标红的词）
  • 右侧问题卡片上点「收藏」

查看与编辑

  • 页头「我的词库 N」按钮 → 打开词库视图；再点一次切回审阅
  • 右侧面板「词库」标签 → 同一视图
  • 每行可以写备注（释义 / 例句），点 ✕ 删除，顶部搜索框过滤
  • 「收藏的词不再报拼写错误」是总开关；关掉后收藏的词照常参与拼写检查
  • 导出 / 导入 JSON —— 换浏览器或清缓存前记得导出
词库存在浏览器 localStorage 里，换设备不会同步。要跨设备用，得接后端（见 E 档配置或自行加账号体系）。

C. 服务端启动参数

启动命令骨架：

cd /Users/wang/tools/LanguageTool-6.6
/Users/wang/tools/java21/Contents/Home/bin/java -Xmx2g \
  -cp languagetool-server.jar org.languagetool.server.HTTPServer \
  --port 8081 --allow-origin --config lt.properties
参数作用建议
--port / -p监听端口，默认 8081本机 8081 即可
--public允许外部机器访问；不加只能本机连部署到服务器必须加
--allow-origin [ORIGIN]加 Access-Control-Allow-Origin 响应头，浏览器跨域直连需要开发留空（= *）；生产写具体域名
--config FILE读 properties 配置文件，D 表的所有项都写在这里生产必配
--languageModel DIR挂 n-gram 语言模型，英文混淆词（their/there、affect/effect）准确率明显提升有条件就挂，见 D 表
--premiumAlways无账号也启用 premium 规则（自建自用可开）仅内网自用
--verbose / -v出错时把输入文本打进日志（最多 500 字符）排查时临时开，注意隐私
-XmxJVM 堆大小2g 起；多语言/长文加到 4g

D. 服务端配置项（--config 文件）

按用途分四组。web-editor/server.properties.example 里有可直接改的模板。

性能

配置项说明建议值
maxCheckThreads并行检查线程数上限CPU 核数
cacheSize句子级缓存条数，0 = 关闭（默认）。同一段文字反复查时很有效10000
cacheTTLSeconds缓存存活秒数，设了 cacheSize 时默认 300300
pipelineCaching缓存内部处理链，减少重复初始化true
maxPipelinePoolSize上面那个池的大小100
pipelineExpireTimeInSeconds池里对象多久过期3600
pipelinePrewarming启动时预热（启动会明显变慢，但首个请求快）长驻服务 true
maxCheckTimeMillis单次检查的时间上限，超时中断，防止一条请求拖死60000
maxWorkQueueSize排队超过这个数直接拒绝请求200

限流与安全

配置项说明建议值
requestLimit每个周期内每 IP 的请求数上限60
requestLimitPeriodInSeconds上面的周期长度（秒）60
requestLimitInBytes同周期内的字节总量上限按需
timeoutRequestLimit超时请求数上限10
blockedReferrers屏蔽的 Referer / Origin，逗号分隔按需
trustXForwardForHeader在反代后面时按 X-Forwarded-For 的真实 IP 限流反代部署时 true
disabledRuleIds服务端层面全局关掉某些规则（比前端忽略更彻底）按需
premiumOnly只启用 premium 规则一般不开

文本长度

配置项说明建议值
maxTextLength单次请求文本上限，超过直接报错。本机实测默认 2147483647（等于不限）20000
maxTextHardLength硬上限，带特殊 token 的用户也突破不了50000
maxSpellingSuggestions拼写错误最多给几条建议（仅 Hunspell 系语言），纯性能项5
maxErrorsPerWordRate每词错误率超过阈值就中止（防恶意文本）0.5
前端的分段阈值要和这里对齐：maxTextLength 设 20000，就把页面的「分段大小」也设 20000，超长文会自动切片，用户不会撞到报错。

语言模型 / 扩展

配置项说明
languageModeln-gram 目录（含 1grams/2grams/3grams 的 Lucene 索引），显著提升混淆词判断
fasttextModel / fasttextBinary更好的语种检测模型（fasttext），多语混写场景用
rulesFile规则开关文件（如 .languagetool.cfg），按项目批量控制规则
lang-xx / lang-xx-dictPath给 LT 不支持的语言加「只查拼写」支持，如 lang-tr=Turkish + 对应的 hunspell .dic

E. 三档推荐配置

① 本机自用（现在的状态）

java -Xmx2g -cp languagetool-server.jar org.languagetool.server.HTTPServer \
  --port 8081 --allow-origin

不用配置文件。前端连 http://localhost:8081。适合一个人写东西。

② 内网多人

maxCheckThreads=8
cacheSize=10000
cacheTTLSeconds=300
pipelineCaching=true
requestLimit=120
requestLimitPeriodInSeconds=60
maxTextLength=20000
maxCheckTimeMillis=60000

启动加 --public --config lt.properties --allow-origin http://内网域名。

③ 公网

在 ② 的基础上：

  • 服务只监听 127.0.0.1，前面用 Nginx/Caddy 反代（见 F），前端填同域路径，彻底没有 CORS
  • 打开 trustXForwardForHeader=true，否则所有人共用一个限流额度
  • 鉴权放在网关（登录态 / JWT / Basic），不要指望 LT 自己
  • maxTextHardLength=50000、maxWorkQueueSize=200 兜底

F. 反代与鉴权

反代是最省事的做法：前端把「服务器地址」填成 /lt，浏览器同域请求，不触发跨域。

# Nginx
location /lt/ {
    proxy_pass         http://127.0.0.1:8081/;
    proxy_set_header   Host $host;
    proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 4m;
    # 鉴权示例：先过一层 basic auth
    # auth_basic           "proofread";
    # auth_basic_user_file /etc/nginx/.htpasswd;
}
# Caddy
handle_path /lt/* {
    reverse_proxy 127.0.0.1:8081
}
用了反代就不要再给 LT 加 --allow-origin（等于向全网开放跨域）。

G. 故障排查

现象原因与处理
页头红点「无法连接服务器」服务没起，或地址写错。先 curl http://localhost:8081/v2/languages 看有没有 JSON
浏览器控制台报 CORS启动时没带 --allow-origin；或生产环境加了具体域名但前端域名不匹配
检查很慢（秒级）首次请求要加载语言包，属正常；持续慢就加 cacheSize、pipelineCaching，并确认 JVM 堆够
长文报错 / 卡住maxTextLength 太小；把前端「分段大小」调到同一数值
某些词一直被标红点「收藏」（进白名单）或「永久忽略」；想全局关就在 disabledRuleIds 里写规则 ID
换浏览器后词库空了词库只在 localStorage；从原浏览器「导出 JSON」再「导入」
服务端 OOM加大 -Xmx；调小 cacheSize；限制 maxCheckThreads
本页是静态说明，改了配置不用重新构建前端；start.sh 里可以固定你的启动参数。
